# testAgents

Конвейер из пяти агентов Claude Code. Задача проходит анализ, план и реализацию, и после каждого этапа проверяющий пытается доказать, что этап провален.

## Как запустить

Открой эту папку в Claude Code и напиши задачу обычным сообщением. Сессия стартует как `orchestrator` (это задано в `.claude/settings.json`): он сам проведёт задачу по этапам и в конце даст доклад.

## Агенты

| Агент | Модель | Что делает | Результат |
|---|---|---|---|
| `orchestrator` | Fable | Ведёт задачу по этапам, вызывает остальных, докладывает | `task.md`, `report.md` |
| `analyst` | Fable | Разбирает задачу | `analysis.md` |
| `planner` | Fable | Пишет план по принятому анализу | `plan.md` |
| `coder` | Sonnet, effort low | Реализует план без собственных решений | код, `code-report.md` |
| `reviewer` | Fable, effort high | Доказывает, что этап провален | `review-<этап>-N.md` |

Определения лежат в `.claude/agents/`. Модель меняется полем `model`, глубина рассуждений — полем `effort`.

## Порядок

```
задача → analyst → reviewer → planner → reviewer → coder → reviewer → доклад
```

- `VERDICT: PASS` — этап принят, идём дальше.
- `VERDICT: FAIL` — этап возвращается автору и снова идёт на проверку.
- `FAIL` засчитывается только при блокирующем дефекте с доказательством.
- Не больше трёх попыток на этап. После третьего `FAIL` оркестратор останавливается и приносит обе позиции тебе.
- Если coder не может выполнить план как написано, план возвращается planner.
- Если у analyst есть блокирующие вопросы, оркестратор задаёт их тебе до проверки анализа.

## Где результаты

Каждая задача получает папку `pipeline/NNN-имя/` со всеми промежуточными файлами и итоговым `report.md`.
